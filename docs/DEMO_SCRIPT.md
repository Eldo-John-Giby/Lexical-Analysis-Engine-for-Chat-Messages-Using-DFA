# LexiChat DFA: 3-Minute Live Demonstration Script

**Project Title:** Lexical Analysis Engine for Chat Messages Using Deterministic Finite Automata  
**Target Duration:** Exactly 3 minutes (180 seconds)  
**Tone:** Confident, technical, and theory-driven.

---

### Phase 1: The Hero Playground (0:00 &ndash; 0:40)
- **Action:** Open application. Top bar displays real status pill: *"Engine ready: 29 rules, 137 DFA states, built in 34.2 ms"*.
- **Action:** Select preset **"Hackathon night"**. The live editor lights up with token highlight overlays, and chips animate into the token stream.
- **Talking Points:**
  > "Good morning, professors. This is LexiChat DFA, a from-scratch lexical analysis engine for informal chat text. Every token you see on this screen comes directly from our own compiled Deterministic Finite Automata—without using lexer generators or JavaScript RegExp in the lexing path."
  > "Notice how complex chat constructs tokenize effortlessly: broadcast mentions like `@everyone`, ZWJ emoji sequences like `👨‍💻` and flags `🇮🇳`, Indian Rupee currency `₹1,299.50`, and Hinglish words."

---

### Phase 2: Maximal Munch & Rollback Trace Player (0:40 &ndash; 1:10)
- **Action:** Click the URL token `https://vit.ac.in/x.` in the chips strip or editor, or click **"Next Rollback"** in the bottom trace player dock. Hit **Play**.
- **Visual:** The character tape advances cell-by-cell. At the trailing period `.`, the read head pauses, marks the accepting state, encounters the dead state on whitespace, and visibly rewinds back to the dot with the narration: *"Maximal munch: rolled back 1 char to last accepting state"*.
- **Talking Points:**
  > "Here is our trace player visualizing the maximal munch longest-match algorithm. Watch the read head consume the URL. Because URLs cannot end in a period, the DFA explores forward, reaches a dead state, and rolls back to the last accepting state candidate. The URL is emitted, and the period is correctly tokenized as punctuation."

### Phase 3: Automata Explorer (1:10 &ndash; 1:40)
- **Action:** Switch to the **Automata Explorer** tab. Select the **URL rule DFA**, then toggle to **Master DFA** and enable **Focus Mode**.
- **Talking Points:**

### Phase 4: The Construction Lab (1:40 &ndash; 2:15)
- **Action:** Switch to the **Construction Lab** tab. Load the textbook preset `(a|b)*abb`.
- **Step through:**
  1. **AST:** Show the parsed syntax tree.
  2. **Thompson NFA:** Point out the $\epsilon$-transitions and fragment composition.
  3. **Subset Construction:** Show the worklist step table with move sets and $\epsilon$-closures.
  4. **Moore Minimization:** Show round-by-round partition splits reducing states down to the textbook 4-state minimal DFA.
  5. **Run it:** Type `ababb` and show side-by-side NFA vs DFA acceptance.
- **Talking Points:**
  > "The Construction Lab demonstrates the theoretical answer key for our viva. For any regular expression, we step through AST parsing, Thompson NFA construction, subset powerset determinization, and Moore partition refinement. For the classic textbook expression `(a|b)*abb`, our minimization algorithm produces the exact 4-state minimal DFA."

### Phase 6: ReDoS Showdown & Closing (2:40 &ndash; 3:00)
- **Action:** Switch to the **Benchmarks** tab. Click **"Run Live Showdown"**.
- **Visual:** The ReDoS chart renders. Native RegExp shoots up exponentially, while our DFA line stays completely flat at 0.02 ms.
- **Talking Points:**
  > "Finally, the ReDoS showdown. Testing the ambiguous pattern `(a+)+` against adversarial inputs, native regular expression engines experience catastrophic exponential backtracking. Because our DFA tracks exactly one state at every step, execution remains strictly linear $O(n)$ with zero backtracking."
  > "Every token, graph, and trace you saw today was generated from scratch by our own compiler. Thank you."
